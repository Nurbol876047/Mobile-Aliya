# FloraCare — техникалық сипаттама

**Қолданба түрі:** мобильді (Android + iOS), Flutter 3 / Dart 3.
**Мақсаты:** үй өсімдіктерінің жапырақ фотосы бойынша күйін бағалау және
бақылау тарихын жүргізу.
**Тілдері:** қазақша, орысша, ағылшынша (профильден ауысады; ЖИ де сол тілде жауап береді).

## 1. Пайдаланушылар және мақсаттар

| Пайдаланушы | Мақсаты |
|---|---|
| Үй өсімдігін ұстаушы (негізгі) | Өсімдігінің сарғаюын ерте байқау, күтім тарихын есте сақтау |
| Жаңадан бастаған | Қай өсімдікке назар аудару керегін бір қарағанда түсіну |
| Оқытушы / агроном-кеңесші | Бірнеше өсімдіктің динамикасын салыстыру, фото тарихын көрсету |

**Үш негізгі пайдалану жағдайы (use case):**
1. **Жаңа өсімдік тіркеу** → атауы, түрі, орны → тізімде пайда болады.
2. **Жапырақты талдау** → камера/галерея → түс пайызы мен күй → күнделікке сақтау.
3. **Тарихты қарау** → күнделіктен іздеу/сүзу/сұрыптау немесе өсімдік бетіндегі
   жасыл үлесінің диаграммасы арқылы үрдісті бағалау.

## 2. Функционалдық талаптар (тексеру критерийлерімен)

| № | Талап | Тексеру критерийі |
|---|---|---|
| F1 | Өсімдік қосу (атауы міндетті, түрі мен орны міндетті емес) | Бос атаумен сақтау «Өсімдік атауын енгізіңіз» қатесін береді; дұрыс атау тізімде көрінеді |
| F2 | Өсімдікті және оның бақылауларын жою | Растау терезесінен кейін өсімдік те, оның жазбалары да (CASCADE) жоғалады |
| F3 | Камерадан немесе галереядан фото жүктеу | «Камерадан» камераны ашады (вебте — қолданба ішіндегі тікелей көрініс `getUserMedia` арқылы, телефонда — жүйелік камера), «Галереядан» — файл таңдағышты; таңдалған фото экранда көрінеді. Камераға рұқсат жоқ/камера жоқ болса — қазақша (таңдалған тілдегі) хабарлама және «Галереядан» түймесі (`test/camera_screen_test.dart`) |
| F4 | Фото форматы мен өлшемін тексеру | `.gif`, кеңейтімсіз файл және 10 МБ-тан үлкен файл қатемен қабылданбайды |
| F5 | Жапырақ түсін жіктеу (сау жасыл / сарғаю / қоңырлану үлесі) Gemini арқылы | Жауапта үш пайыз бар, қосындысы 100-ге келтіріледі (`AiAnalysis.fromJson` тесттері) |
| F6 | Күйді анықтау (Дені сау / Назар аудару керек / Қауіпті жағдай) және жеке кеңес беру | Күй тек ЖИ жауабынан алынады; талданбаған өсімдік «Әлі тексерілмеген» деп көрсетіледі, «дені сау» деп болжанбайды |
| F7 | Сканды тарихқа сақтау (фото, күні, пайыздар, жазба); өсімдікке тіркеу міндетті емес | ЖИ нәтижесі бірден «Тарих» тізімінде көрінеді; тіркелмеген скан «Өсімдікке тіркелмеген» деп белгіленеді және кейін «Тіркеу» арқылы өсімдікке (немесе жаңа өсімдікке) байланады |
| F8 | Күнделіктен іздеу (өсімдік атауы және жазба мәтіні бойынша) | «сарғай» сұрауы тек сол жазбаны қалдырады, регистр ескерілмейді |
| F9 | Күй және кезең (7 / 30 күн / барлығы) бойынша сүзу | Сүзгі қосылғанда тізім тиісті жазбалармен ғана қалады |
| F10 | Сұрыптау: күні, атауы, күй ауырлығы, жасыл үлесі + кему/өсу | Әр кілт үшін тізім реті тестте тексерілген |
| F11 | Өсімдік бетінде жасыл үлесінің тарихы (диаграмма) және үрдіс | ≥2 бақылау болғанда «Жақсарып келеді ↑ / Нашарлап барады ↓ / Тұрақты →» көрсетіледі |
| F13 | ЖИ арқылы фото талдау: диагноз, денсаулық бағасы 0–100, жапырақ түсінің жіктелуі мен түсіндірмесі, белгілер, себептер, 4–6 кеңес, болжам, өсімдік туралы деректер (латынша атауы, тұқымдасы, отаны, сипаттамасы, уыттылығы, қызықты дерек), күтім талаптары (жарық, суару, температура, ылғалдылық, топырақ, тыңайтқыш), келесі тексеру мерзімі | Нақты өсімдік фотосы ≤15 с ішінде қазақша қорытынды береді; өсімдік емес суретке `is_plant=false` және төмен сенімділік қайтарады |
| F14 | ЖИ қолжетімсіз болса — жалған нәтиже көрсетпеу | Интернет/кілт жоқ немесе модельдер жүктелген кезде түсінікті хабарлама мен «Қайталау» түймесі шығады; бақылау тек нақты ЖИ нәтижесімен сақталады |
| F12 | Деректердің сақталуы және қараңғы тақырып | Қолданбаны жауып қайта ашқанда деректер мен тақырып таңдауы сақталады |
| F15 | Интерфейс тілін ауыстыру (қазақша / орысша / ағылшынша) | «Профиль → Тіл» таңдауы бірден бүкіл интерфейсті ауыстырады, қайта ашқанда сақталады; ЖИ сұранысына `lang` беріліп, жауап сол тілде келеді (`test/l10n_test.dart` үш тілдің толықтығын және қолданылған кілттерді тексереді) |
| F16 | Өсімдіктер анықтамалығы (27 түр: фото, сипаттама, күтім, уыттылық) | «Өсімдіктер → Анықтамалық» қойындысында іздеу мен санат сүзгісі жұмыс істейді; «Менікіне қосу» өсімдікті тізімге қосады |

## 3. Функционалдық емес талаптар

| № | Талап | Тексеру критерийі |
|---|---|---|
| N1 | **Өнімділік.** Фото талдау интерфейсті бөгемейді | Фотоны оқу/кішірейту `compute()` арқылы бөлек isolate-та; Gemini-ге ≈768 px JPEG жіберіледі (баяу желіде де тез); ЖИ жауабы әдетте 5–15 с |
| N2 | **Құпиялылық.** Интернетке дерек жіберілмейді, аккаунт қажет емес | Қолданбада желілік сұраныс жоқ; дерекқор мен фото қолданбаның sandbox қалтасында |
| N3 | **Тұрақтылық.** Қате енгізу қолданбаны құлатпайды | Барлық қате жағдай `ValidationError` арқылы хабарлама түрінде көрсетіледі; тесттер шеткі жағдайларды қамтиды |
| N4 | **Тасымалданушылық.** Бір код базасы — Android және iOS | `flutter build apk` және `flutter build ipa` бірдей `lib/` кодынан жиналады |
| N5 | **Қолжетімділік/локализация.** Интерфейс үш тілде (қазақша/орысша/ағылшынша), тақырып жарық/қараңғы | Барлық мәтін `lib/l10n/l10n.dart` ішінде, `tr('кілт')` арқылы алынады; тест әр кілттің үш тілде де бар екенін және интерфейстегі барлық кілттің аударылғанын тексереді; жүйелік қаріп өлшемі ескеріледі |
| N6 | **Тестпен қамту.** Бизнес-логика эмуляторсыз тексеріледі | `flutter test` — валидация, іздеу/сүзу/сұрыптау, үрдіс, ЖИ жауабын тексеру; UI-ға тәуелсіз |

## 4. Деректер моделі (3 кесте)

```
┌─────────────────────┐        ┌──────────────────────────┐        ┌──────────────┐
│ plants              │        │ observations             │        │ diagnoses    │
├─────────────────────┤        ├──────────────────────────┤        ├──────────────┤
│ id    INTEGER PK    │1      ∞│ id         INTEGER PK    │∞      1│ code   TEXT PK│
│ name  TEXT NOT NULL ├────────┤ plant_id   INTEGER FK    │────────┤ title  TEXT   │
│ species    TEXT     │        │ thumb      TEXT (base64) │        │ advice TEXT   │
│ location   TEXT     │        │ photo_path TEXT          │        └──────────────┘
│ created_at TEXT     │        │ taken_at   TEXT (ISO)    │         healthy/warning/
└─────────────────────┘        │ status     TEXT FK       │         critical
                               │ green_pct  REAL          │
                               │ yellow_pct REAL          │
                               │ brown_pct  REAL          │
                               │ note       TEXT          │
                               └──────────────────────────┘
```

- `plants 1 — ∞ observations` (`ON DELETE CASCADE`): өсімдік жойылса,
  оның барлық бақылаулары да жойылады.
- `observations.status → diagnoses.code`: күй мен кеңес мәтіні бір жерде сақталады.
- Индекс: `idx_obs_plant_date (plant_id, taken_at)` — өсімдік тарихын жылдам оқу.
- `plants.name` ұзындығы 1..60 таңба болуы `CHECK` арқылы дерекқор деңгейінде де
  бекітілген (қосымша қорғаныс қабаты).

## 5. Фото өңдеу

0. Камерадан алынған кадр: вебте `getUserMedia` ағыны `<video>` элементінде көрсетіледі
   (`HtmlElementView`), түсіру кезінде кадр `<canvas>`-қа салынып, JPEG (0.92) болып алынады;
   алдыңғы камерада көрініс те, сурет те айнадай түзетіледі. Телефонда жүйелік камера
   қосымшасы ашылады (`image_picker`). Камера ағыны экраннан шыққанда тоқтатылады
   (құрылғы индикаторы сөнеді).
1. Файл тексеріледі: тек JPG/PNG/WEBP, ≤10 МБ, ≤40 мегапиксель.
2. Фото бөлек isolate-та оқылып, екі көшірме жасалады: ≈480 px (күнделікке сақталады)
   және ≈768 px (Gemini-ге жіберіледі).
3. Gemini жауабы JSON-схема бойынша тексеріліп, бақылау ретінде сақталады.
   Құрылғыда «болжам» нәтиже есептелмейді — барлық баға тек ЖИ-ден.

## 6. ЖИ интеграциясы

```
[Қолданба] --фото (768px JPEG)--> [backend/server.py] --x-goog-api-key--> [Gemini API]
     ^                                   |  тексеру: формат, өлшем, JSON-схема
     +---------- қалыпқа келтірілген JSON (status, score, diagnosis, advice…) -----+
```

- Модельдер реті: `gemini-2.5-flash` → `gemini-3.1-flash-lite` → `gemini-flash-lite-latest` →
  `gemini-flash-latest`. Уақытша қатеде (5xx, жүктеме салдарынан 429) сол модель 1,5 с кейін
  бір рет қайталанады; 404, таймаут немесе шектеу таусылғанда (429 «quota») бірден келесі
  модельге көшеді — бос күтуге уақыт кетпейді; бір талдауға жалпы шек — 75 с. Әр әрекет сервер логына жазылады (кілтсіз).
- Барлық модель жүктелген болса, пайдаланушыға «Қайталау» түймесі бар түсінікті
  қазақша хабарлама көрсетіледі; жалған/шаблон нәтиже көрсетілмейді.
- Жауап `responseSchema` арқылы қатаң JSON; сервер мен қолданба оны қайта тексереді
  (`normalize` / `AiAnalysis.fromJson`): пайыздар 100-ге келтіріледі, шектен шыққан
  мәндер қиылады, белгісіз күй → «warning», ұзын мәтін қысқартылады.
- Промпт модельге ойдан диагноз құрастырмауды және сенімсіздігін ашық көрсетуді талап етеді.
- Промпт соңына жауап тілінің нұсқауы қосылады (`aiLanguageDirective`): пайдаланушы
  таңдаған тіл сұранысқа `lang` өрісімен беріледі, сервер де сол нұсқауды қояды.
- Интерфейсте сервис атауы көрсетілмейді («ЖИ талдауы»); модель атауы клиентке жіберілмейді, тек сервер логында.
- Өсімдік жоқ суретке «өсімдік туралы» және «күтім» бөлімдері көрсетілмейді (ойдан толтыру болмауы үшін).
- ЖИ нәтижесі бақылаумен бірге `observations.ai_json` бағанында сақталады.

## 7. Қауіпсіздікті басқару

**Неліктен бұл технология таңдалды?**
Flutter/Dart — бір код базасынан Android және iOS үшін нативті қолданба береді;
камера, галерея, SQLite үшін ресми, қолдауы бар пакеттер бар; ауыр есептеуді
isolate-қа шығаруға болады; бизнес-логика таза Dart модулі ретінде
эмуляторсыз тестіленеді.

**Деректер қалай қорғалады?**
- Қолданба **желіге ештеңе жібермейді**, аккаунт пен бұлт қажет емес.
- Дерекқор мен фотолар қолданбаның жеке қалтасында (Android/iOS sandbox),
  басқа қолданбалар оқи алмайды.
- Фото кездейсоқ атпен (`Random.secure`) сақталады — файл аты бойынша болжау мүмкін емес.
- Камера ағыны тек сканер экранында ашық тұрады және экраннан шыққанда дереу тоқтатылады;
  видео ешқайда жіберілмейді, тек түсірілген кадр ғана өңделеді.
- Барлық SQL сұраулар **параметрленген** (`?` аргументтері) — SQL injection мүмкін емес.
- Пайдаланушы енгізген мәтін ұзындығы шектелген (атау 60, жазба 500 таңба),
  фото 10 МБ және 40 Мпикселден аспайды — жадты шамадан тыс жүктеу мен
  «decompression bomb» тәуекелі азаяды.
- Өсімдікті жою кезінде оның фотолары да дискіден өшіріледі.
- **Gemini API кілті** тек серверде (`.env`, рұқсаты 600) сақталады, браузерге/қолданбаға
  берілмейді, URL-ге емес `x-goog-api-key` тақырыбына қойылады, логқа жазылмайды.
  `.env` және `secrets.json` `.gitignore`-да. Сервер тек `web_prototype/` қалтасын
  таратады — `.env`-ке HTTP арқылы жету мүмкін емес (тексерілді: 404).
- Сервер әдепкіде тек `127.0.0.1`-де тыңдайды; CORS тек localhost origin-дерге рұқсат.
- Серверге келетін фото тексеріледі: тек JPEG/PNG/WEBP, ≤10 МБ, сұраныс ≤12 МБ.
- **Құпиялылық:** ЖИ қосулы болса, фото талдау үшін Google серверіне жіберіледі
  (тек фото мен өсімдік атауы, жеке дерек жоқ). ЖИ өшірулі режимде ештеңе жіберілмейді.
- Тікелей режимде (`GEMINI_API_KEY` APK-да) кілтті APK-дан шығарып алуға болады —
  сондықтан ол тек оқу демосы үшін; өнімде сервер режимі қолданылады.

**Қандай шеткі жағдайлар тексерілді?** (`test/logic_test.dart`)
бос/ұзын атау, бос және тым ұзын жазба, рұқсат етілмеген кеңейтім, нөлдік және
10 МБ-тан үлкен файл, дәл 10 МБ шегі, бос тізімді сүзу, белгісіз сұрыптау
кілті/күй/теріс күн саны, кезең шекаралары, 1 мәннен тұратын үрдіс, дәл ±5 айырма.
ЖИ (`test/ai_test.dart`): өрістері жоқ жауап, шектен шыққан балл/сенімділік,
теріс пайыздар, белгісіз күй мен шұғылдық, мәтін түріндегі сандар, тым ұзын
мәтін, бұзылған JSON, бос `candidates`, өсімдік емес сурет, сақтау/оқу айналымы.

**Қосымшаны екінші платформада іске қосу үшін не қажет?**
Код өзгермейді. iOS үшін macOS + Xcode + CocoaPods, Apple Developer тіркелгісі
(Bundle ID, сертификат, provisioning profile) керек: `flutter build ipa`.
Android үшін Android SDK + JDK 17: `flutter build apk`. Платформаға тән жалғыз
айырмашылық — рұқсат мәтіндері (`Info.plist` / `AndroidManifest.xml`).
Вебте `sqflite` жұмыс істемейтіндіктен, алдын ала қарау нұсқасында сол интерфейсті
іске асыратын `prefs_repo.dart` қоймасы қолданылады (шартты импорт).
